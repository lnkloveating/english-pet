# 声生岛 App MVP 开发计划

版本：V1.0  
周期：6 周  
目标平台：Android、iOS 真实设备  
技术基线：Expo SDK 57、React Native、TypeScript、FastAPI

## 1. MVP 交付目标

在 6 周内交付一个可供小规模家庭试用的移动 App，使孩子能够：

1. 在监护人完成最小同意流程后创建匿名档案。
2. 进入一个引导式英语对话场景。
3. 录制一句英语并提交。
4. 收到宠物的文字和语音回复。
5. 获得基础声果与轻量成长反馈。
6. 结束会话后查看积极、非羞辱性的学习总结。
7. 由监护人查看开口次数、时长、连续轮数和近期主题。

MVP 成功标准：至少 5–10 个家庭可以在真实 Android/iOS 设备上，独立完成一次 5 分钟英语对话，且核心链路无阻断。

## 2. MVP 范围

### 必须完成（P0）

- 首页、对话页、会话总结页、监护人入口。
- 麦克风授权、开始/停止录音、上传状态和失败重试。
- ASR → Agent → TTS 完整闭环。
- 引导式对话模式，至少包含 repeat、choose、answer 三种任务。
- 匿名孩子档案、会话记录和学习者画像持久化。
- 有效开口基础声果、偶发 bonus 和简单宠物成长状态。
- 儿童隐私、安全转移、超时、弱网和服务异常处理。
- Android/iOS 开发构建、内部测试包和基础埋点。

### 应该完成（P1）

- 三个主题场景，例如动物、学校生活、日常活动。
- 宠物创建：描述、生成状态、候选选择。
- 家长报告：有效开口、主动开口、平均句长、连续轮数。
- TTS 自动播放开关、字幕开关和音量提示。
- 会话历史与继续上次对话。

### 暂不进入 MVP

- 全双工实时语音和打断式对话。
- 排行榜、公开社交、复杂商城和大地图。
- 自训练模型、儿童语音长期保存和原始音频训练。
- 自由生成完整 3D 模型、自动 rig。
- 面向孩子展示语法分、发音排名、红叉或负面评价。

## 3. 当前项目基线

仓库已有以下能力：

- `app/mobile`：Expo SDK 57 + React Native + TypeScript 单页 Demo。
- `app/backend`：FastAPI BFF，提供会话回合和宠物任务入口。
- `agent`：对话、奖励、学习者画像和安全策略骨架。
- `pet_pipeline`：宠物生成任务状态机和 Provider 骨架。
- `shared`：OpenAPI、JSON Schema、Python/TypeScript 合同。
- `docker-compose.yml`：三个后端服务的本地编排。

当前主要缺口：页面路由、真实录音、ASR/TTS、持久化、认证/监护人流程、报告、真机测试和发布配置。

## 4. 技术方案

### 移动端

- 保留现有 `app/mobile`，不新建第二个 App 工程。
- 引入 Expo Router，将单个 `App.tsx` 迁移为文件路由。
- 使用 `expo-audio` 完成录音和播放。
- 第一版采用“录制完整音频文件 → 上传 → 返回结果”的半双工方案。
- 会话临时状态使用轻量 store；服务端数据以 API 返回为准。
- 令牌使用系统安全存储，不在客户端保存模型或云服务密钥。

建议页面结构：

```text
app/mobile/
├── app/
│   ├── _layout.tsx
│   ├── index.tsx
│   ├── onboarding/
│   ├── conversation/[sessionId].tsx
│   ├── summary/[sessionId].tsx
│   ├── pet/
│   └── guardian/
├── src/
│   ├── api/
│   ├── audio/
│   ├── components/
│   ├── features/
│   ├── store/
│   └── theme/
└── assets/
```

### 服务端

- Mobile 只访问 `app/backend`，由 BFF 聚合 Agent、ASR/TTS 和宠物服务。
- 本地开发可使用 SQLite；试用环境使用 PostgreSQL。
- 原始音频默认只用于当次识别，处理完成后删除。
- 所有跨服务字段先进入 `shared/contracts/openapi.yaml`，再实现客户端和服务端。
- 为请求设置超时、幂等键、统一错误码和可追踪的 request ID。

### 暂缓 WebSocket 的原因

半双工录音已经能验证孩子是否愿意持续开口，同时实现成本、真机兼容和故障恢复更可控。只有当实测表明等待时间明显影响留存时，再进入流式 ASR、流式 TTS 和打断机制。

## 5. 六周里程碑

### 第 0 周：工程基线（1–2 天）

交付内容：

- 安装依赖，跑通 `docker compose up --build`。
- 跑通当前文字输入 Demo 的端到端回合。
- 建立 App 功能分支和环境变量约定。
- 引入 Expo Router、`expo-audio` 和统一主题变量。
- 整理 monorepo 的 TypeScript 合同引用，确保 Metro 和 EAS 可解析。
- 配置正式应用标识的占位值、开发/测试环境 API 地址。

验收标准：

- Android 或 iOS 至少一台真机能打开开发构建。
- Mobile → BFF → Agent stub 回合成功。
- 类型检查和现有后端测试通过。

### 第 1 周：三屏可点击产品骨架

交付内容：

- 首页、对话页、总结页完成导航和基础视觉。
- 可选择年级与主题，创建匿名本地会话。
- 对话页接入现有文字回合 API。
- 统一 loading、空状态、错误状态和重试交互。
- 完成麦克风权限说明页和监护人入口占位。

验收标准：

- 用户能完成“首页 → 对话 3 回合 → 总结 → 再来一次”。
- 小屏 Android 和主流 iPhone 尺寸无明显布局问题。
- 孩子端没有语法分数、红叉或羞辱性文案。

### 第 2 周：真实语音闭环

交付内容：

- 实现录音、停止、取消、试听和重新录制。
- 新增音频上传接口与文件大小、时长、格式校验。
- 接入首个 ASR Provider，并保留 stub Provider。
- 接入首个 TTS Provider，客户端播放宠物回复。
- 增加上传、识别、思考、播放四类状态。
- 实现超时、断网、权限拒绝和重复提交恢复。

验收标准：

- 真实设备连续完成 10 个语音回合无崩溃。
- 失败后不丢失当前会话，用户可以重新提交。
- 默认不持久保存原始音频，日志不包含完整儿童自由文本。

### 第 3 周：对话质量与持久化

交付内容：

- repeat → choose → answer 三种对话任务联调。
- 学习者画像和会话状态写入数据库。
- 实现基础声果、bonus、连续回合与成长状态。
- 完成 20–50 个黄金对话用例及自动回归。
- 限制回复长度、问题数量和难度上升幅度。
- 建立安全内容转移和高风险提示流程。

验收标准：

- 退出并重新打开 App 后可恢复档案和历史进度。
- 所有有效英语开口都有基础奖励。
- 黄金用例的字段、奖励和安全决策符合合同。

### 第 4 周：宠物创建与家长报告

交付内容：

- 宠物描述、生成等待、失败、审核和选择页面。
- 轮询宠物任务状态并缓存最终资产。
- 会话总结显示积极回顾、自然复述和今日建议。
- 家长报告展示开口次数、主动开口、平均句长、连续轮数。
- 增加监护人同意、数据删除和退出入口。

验收标准：

- 用户能创建并选择一个安全的宠物形象。
- 家长数据能追溯到真实会话，但不暴露不必要的原始内容。
- 孩子端与监护人端信息边界清晰。

### 第 5 周：可靠性、安全与可观测性

交付内容：

- BFF 增加认证、限流、幂等、结构化日志和 request ID。
- 统计 ASR、Agent、TTS 分段延迟与失败率。
- 处理应用切后台、来电中断、耳机断开和系统回收。
- 完成隐私诱导、危险建议、成人内容和 prompt injection 红队测试。
- 补充错误码、降级回复和运营排查文档。

验收标准：

- 网络中断和服务超时不会导致 App 崩溃或重复扣/发奖励。
- 日志中没有密钥、姓名、学校、地址、联系方式或原始音频。
- 高风险测试样例全部进入安全转移或可信成人提示。

### 第 6 周：Beta 构建与家庭试用

交付内容：

- 配置 EAS development/preview 构建。
- 完成图标、启动图、权限文案、版本号和包名。
- Android/iOS 真机回归与性能检查。
- 发布内部测试包，组织 5–10 个家庭试用。
- 收集核心指标、崩溃、延迟和访谈反馈。

验收标准：

- 测试者无需开发人员协助即可安装并完成首次会话。
- P0 流程无阻断级缺陷。
- 已形成继续迭代、调整方向或停止投入的明确结论。

## 6. 接口增量清单

在实现功能前，建议补充或确认以下 `/v1` 合同：

- `POST /v1/audio/transcriptions`：上传一次录音并返回转写。
- `POST /v1/sessions`：创建会话和选择对话模式。
- `POST /v1/sessions/{id}/turns`：提交转写及音频元数据。
- `POST /v1/speech`：生成宠物回复音频，或由 turn 接口返回音频 URL。
- `POST /v1/sessions/{id}/complete`：结束会话并生成总结。
- `GET /v1/reports/summary`：监护人报告聚合。
- `POST /v1/consents`：记录监护人同意版本。
- `DELETE /v1/children/{id}`：删除孩子相关数据。
- `GET /v1/pets/jobs/{job_id}`：查询宠物生成任务。

是否拆分 ASR/TTS 接口可在合同评审时决定；客户端不应直接调用第三方模型服务。

## 7. 测试与发布门槛

### 自动化测试

- Mobile：类型检查、组件状态、API 映射、录音状态机测试。
- BFF：成功、超时、上游 4xx/5xx、幂等和非法文件测试。
- Agent：黄金对话、奖励、安全和难度策略回归。
- Contract：OpenAPI 与 Python/TypeScript 模型一致性检查。
- E2E：首页 → 录音 → 回复 → 奖励 → 总结的关键路径。

### 每次合并前

- `scripts/check.ps1` 或 `scripts/check.sh` 全部通过。
- 不提交 `.env`、密钥、儿童真实数据和原始音频。
- 合同修改附带兼容性说明和示例 payload。
- 至少完成一次 Android 或 iOS 真机冒烟测试。

### Beta 发布门槛

- 无阻断级和高危隐私缺陷。
- 崩溃恢复、断网重试、权限拒绝均有明确体验。
- 完成监护人同意、删除与数据保留策略审查。
- 儿童教育/安全负责人审核黄金对话集。

## 8. 核心指标

产品指标：

- 每周有效英语开口次数。
- 首次会话完成率。
- 每次会话有效回合数和持续时间。
- 7 日内再次开口比例。
- 孩子主动扩展回答的比例。

工程指标：

- 回合成功率与重试成功率。
- ASR、Agent、TTS 的 P50/P95 延迟。
- 无崩溃会话率。
- 音频上传失败率和各错误码占比。
- 单次有效回合的模型与语音成本。

MVP 不以语法分数提高作为核心成功指标，优先判断孩子是否更愿意持续开口。

## 9. 主要风险与应对

| 风险 | 应对措施 |
| --- | --- |
| ASR 对儿童口音识别不稳定 | 保留重录和文本确认；建立儿童口音测试集；Provider 可替换 |
| 端到端等待时间过长 | 分段记录延迟；先做状态反馈；达到阈值后再评估流式方案 |
| 真机无法访问本地 API | 使用局域网地址或 HTTPS 测试环境；不在真机配置 localhost |
| 音频和隐私泄露 | 默认不保存原始音频；日志脱敏；明确保留和删除策略 |
| Agent 反馈像老师或打击孩子 | 使用自然复述和积极反馈；黄金对话审核；不展示负面分数 |
| 宠物生成成本或等待过高 | 首次使用预置宠物；生成异步化、缓存和失败降级 |
| 范围持续膨胀 | 六周只承诺 P0；P1 以不影响核心说话闭环为前提 |

## 10. 建议的首批开发任务

按以下顺序启动开发：

1. 创建 `feat/app-speaking-loop` 分支。
2. 安装依赖并跑通现有文字回合。
3. 将移动端迁移到 Expo Router 三屏结构。
4. 添加 `expo-audio` 和本地录音状态机。
5. 先以 stub 转写完成 UI 闭环，再增加真实音频上传合同。
6. 接入 ASR Provider，随后接入 TTS Provider。
7. 在真实 Android 设备上完成第一轮端到端验收。

第一阶段的“完成”定义不是页面看起来完整，而是孩子可以在真机说一句英语，并可靠地听到宠物回应。
